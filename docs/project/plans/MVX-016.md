# Plan — MVX-016 project operations and enrichment UI

**Tier:** 1 **Depends on:** MVX-001 synthetic foundation; MVX-009 and MVX-011 before real source/crawler execution

## Outcome

An authenticated organisation member can create a project, configure a Gmail/IMAP/POP lead source, observe bounded sync jobs, run entity-analysis batches, browse contacts/products/roles/history, select entities, and request enrichment through a safe job service. Synthetic jobs work end to end; all external network execution remains disabled by default.

## Acceptance criteria

- Project creation validates name, purpose, languages, retention and budget; records remain organisation scoped.
- Source forms reveal only relevant fields, require TLS for password protocols, encrypt secrets, and never redisplay stored credentials.
- Starting a sync creates an observable job with progress, counters, rate-limit state and errors. Duplicate active jobs are refused.
- Analysis batches create evidence-linked entity/relationship candidates and recompute contact history metrics without modifying raw evidence.
- Reviewers can browse/filter entities, inspect product, role, topic and history tags, and select contacts for enrichment.
- Enrichment jobs have explicit budgets, allowlisted scope, URL/SSRF validation, per-host throttling, provenance and reviewable candidate fields. They do not silently train or publish a model.
- Foreign-organisation, unauthorised, disabled-network, insecure-source, duplicate-job and private-address requests are denied without leaking records or secrets.

## Approach

Extend the modular Django application with a `LeadProject` boundary beneath the organisation, generalized `LeadSource` configurations, persisted `BatchJob`/items, entity tags/relations/metrics, and enrichment profiles/artifacts. Keep provider execution behind adapters and feature flags. Use server-rendered accessible UI and Celery tasks; poll persisted status rather than holding requests open.

## Alternatives rejected

| Alternative | Reason |
| --- | --- |
| Visual node editor first | It adds interaction complexity before the project/source/job lifecycle is proven. |
| Mailbox passwords in environment variables | Multiple sources require individually revocable encrypted credentials and audit events. |
| Autonomous arbitrary-link crawler | It creates SSRF, scope, cost, copyright and personal-data risks. |
| Claim project agents are “trained” after each crawl | No labelled training pipeline, evaluation evidence or model lifecycle exists; reviewed extraction profiles are accurate language. |

## Test and rollback

Add reversible migrations. Test forms, role denials, organisation isolation, secret non-disclosure, duplicate jobs, rate-limit checkpoints, private-address rejection, entity metrics and the project→source→sync→analysis→enrichment journey with mocked boundaries. Roll back application code first; reverse the additive migration only after preserving any new synthetic records. External execution remains off.

## Out of scope

Real mailbox/crawler data, autonomous model training, arbitrary crawling, deletion, CRM delivery, production deployment and quality claims. These remain MVX-003–009 and MVX-011–013.

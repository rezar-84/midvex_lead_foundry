# Plan — MVX-028 editable instance settings

**Tier:** 1 **Depends on:** MVX-027

## Problem
API keys (Google OAuth etc.) require Dokploy env edits + redeploy; the user wants
to add and edit them in the product.

## Outcome
An admin edits whitelisted keys on `/settings/`; secrets are encrypted at rest,
never re-displayed, override env, and are clearable back to env.

## Approach
`InstanceSetting` model (key unique, encrypted_value) + migration 0005;
`runtime_settings.py` whitelist/resolver; consumers (`gmail.py`, `enrichment.py`,
context processor, TOTP issuer) read through `runtime_setting()`; POST endpoint
`instance_setting_update` (manage_users, CSRF, audit event); inline per-row forms.

## Alternatives rejected
| Option | Why not |
| --- | --- |
| Editable policy gates | human-approval surface (AGENTS §9) — must not be web-togglable |
| Plaintext storage | DB dumps would leak credentials; Fernet already in place |

## Failure modes
Missing Fernet key → set fails loudly; unknown key POST → refused; cleared value
→ env fallback (tested).

## Test strategy
Encryption at rest, override precedence, secret never rendered, gate-key POST
refused, analyst denied, clear-restores-env.

## Rollback
Delete rows; revert migration 0005; consumers fall back to env.

## Out of scope
Editing gates/bootstrap secrets; per-organization configuration (MVX-014).

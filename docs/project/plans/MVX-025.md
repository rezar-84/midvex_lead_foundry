# Plan — MVX-025 production deployment readiness (mlf.midvex.com)

**Tier:** 1 **Depends on:** MVX-020

## Problem

Deploying to Dokploy today fails on gaps: nothing runs migrations, the web
container has no healthcheck, evidence storage assumes S3 that doesn't exist yet,
and there is no domain-specific configuration or deployment guide.

## Outcome

A Dokploy compose deployment of `main` at `mlf.midvex.com` starts, migrates,
serves over HTTPS, and survives restarts — with all network policy gates still
false.

## Approach

`scripts/docker-entrypoint.sh` (web only: migrate → gunicorn); compose gains web
healthcheck against `/health/`, `evidence_data` volume on web+worker, postgres
health dependency for the worker, restart policies; `.env.production.example`
documents every variable with mlf.midvex.com values and secret-generation
commands; README gains a Dokploy walkthrough; ADR 0009 records the single-node
topology and its trade-offs.

## Alternatives rejected

| Option | Why not |
| --- | --- |
| Migrations in the Dockerfile build | needs DB at build time; breaks image immutability |
| Migrations in both containers | racy; worker has no reason to own schema |
| Require S3 on day one | blocks deployment on unprovisioned infrastructure; the filesystem backend + volume is already supported and the switch is config-only |

## Affected surfaces

- **Code:** `scripts/docker-entrypoint.sh`, `compose.yaml`,
  `.env.production.example`, `README.md`, ADR 0009. No Python changes.
- **Data:** none. **Contracts:** none.
- **Docs to update:** README, ADR index, backlog, worklog.

## Failure modes

Migration failure → entrypoint exits non-zero, Dokploy keeps the old container;
healthcheck failing → restart; missing env → settings raise at boot (verified
behaviour); lost `TOKEN_ENCRYPTION_KEY` → stored credentials unreadable
(documented in the template).

## Test strategy

- **Unit/regression:** full suite unchanged (no Python edits).
- **Static:** `sh -n` on the entrypoint; `docker compose config -q` with the
  template as env file.
- **Negative:** compose refuses to start without `POSTGRES_PASSWORD` (verified).
- **Manual:** first real deploy follows the release-runbook smoke list — recorded
  there, not claimed here.

## Rollback

Redeploy prior image; compose/env changes are additive; delete the entrypoint and
restore the old CMD path to return to the previous behaviour.

## Out of scope

Backup/restore/rollback drills and production budgets (MVX-008); enabling any
network gate (MVX-009/011); S3 provisioning.

## Assumptions

Single web replica (ADR 0009); Dokploy terminates TLS and sets
`X-Forwarded-Proto`.

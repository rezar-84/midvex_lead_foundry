# Plan — MVX-001 governed standalone pilot foundation

**Tier:** 1 **Depends on:** accountable human and two approvers before merge

## Problem and outcome

The repository contained only an unconfigured process kit. Afterwards it contains a traceable, testable standalone pilot foundation that can process synthetic mail safely, while real mailbox use remains explicitly blocked until authority and retention are approved.

## Approach

Configure the project artifacts and ADRs; build a Django modular monolith with organisation-scoped access, MFA, background connectors, evidence-first records, spam/attachment gates, review UI and CSV; deploy as Dokploy containers; test denial, malformed input, idempotency, purge and rollback paths.

## Alternatives rejected

| Option | Why not |
| --- | --- |
| Odoo module | Couples the core knowledge model and access lifecycle to one destination CRM. |
| Separate React/API/services | Adds deployment and authorisation boundaries before the pilot proves value. |
| IMAP/POP for Gmail | Loses Gmail history/label/thread semantics; POP is not a reconciliation protocol. |
| Subscription CLI as production AI worker | Authentication, output contract and operational limits are weaker than a provider interface. |
| Neo4j/OpenSearch immediately | PostgreSQL relations and search cover the pilot without two more stateful services. |

## Affected surfaces and failure modes

Code, schema, private connector contracts, Dokploy containers and all project truth artifacts are new. External dependencies time out, checkpoint and expose retryable state; scanners fail closed; AI/search fail without inventing output; migrations are additive/reversible; destructive purge requires explicit confirmation and post-checks.

## Test and rollback

Unit, integration, contract, build, scan, accessibility and E2E stages follow the charter. Tests use synthetic data and include foreign organisation, revoked session, malformed MIME, prompt injection, scanner/provider outage and duplicate retries. Rollback pauses workers, deploys the previous image and reverses verified migrations; raw evidence is never implicitly deleted.

## Out of scope and assumptions

No real mailbox, Odoo/CRM write, IMAP/chat, public SaaS, automated outreach or unapproved external AI/search. Unknown owner/approvers, legal authority, processor approval and production budgets remain U1–U4.
